CatJump 사례

사례 1본인 전 범위 구현

10인 PvP 호스트 변경 복구

문제
전용 서버 없는 PUN2 구조에서 진행 권한을 가진 마스터 클라이언트가 나가면 준비⁠·⁠카운트다운⁠·⁠결과 처리가 멈추거나 어긋날 수 있었습니다. 모바일 네트워크라 이벤트 도착 시점도 클라이언트마다 다릅니다.
판단
진행 단계를 룸 속성에 기록해, 호스트가 바뀐 뒤 읽을 복구 기준을 남겼습니다.
구현
경기를 매칭 탐색 → 인원 확정 → 준비⁠·⁠카운트다운 → 플레이 → 결과 단계로 나누고, 예외 상황마다 처리 기준을 정했습니다.
결과
출시 후 카운트다운 불일치, 룸 진입 크래시, 로비 복귀 오류를 수정했습니다.

사례 2본인 설계⁠·⁠구현

이벤트 대사를 공용 시스템으로

문제
공용 시스템 이전에는 이벤트마다 대사와 연출을 코드에 직접 써서, 새 이벤트마다 대사 UI 연결과 종료⁠·⁠예외 처리를 다시 작성했습니다.
판단
대사⁠·⁠연출을 이벤트 코드 밖으로 빼고 공용 시스템이 처리하게 했습니다.
결과
이후 다른 개발자가 만든 이벤트에서도 이 공용 대사 시스템을 썼습니다.

사례 3담당 구현

지급⁠·⁠저장 뒤에 표시

문제
미션 포인트 단계 상자, 광고 추가 개봉, 스킨⁠·⁠재화 가중치 추첨이 한 흐름에 섞이면 팝업⁠·⁠연출만 바꿔도 지급⁠·⁠저장 경로가 같이 바뀝니다.
판단
진행, 보상 결정, 표시를 다른 책임으로 나누고 표시 계층은 확정된 결과만 받게 했습니다.
결과
팝업⁠·⁠개봉 연출은 확정된 결과만 받으므로 표시 쪽을 바꿔도 지급⁠·⁠저장 경로는 그대로입니다. 상자 대상이 아니거나 이미 가진 스킨은 추첨 후보에 들어가지 않습니다.

사례 읽기 : 보상 지급⁠·⁠저장과 표시를 나누고 추첨 전에 후보 제외

    VR 리듬 게임 · 경일게임아카데미 기업 협약 XR 프로젝트 · 2025.02~2025.04

    노트 생성⁠·⁠이동과 BGM⁠·⁠타격음 재생을 맡아, BGM 시작과 노트 도착을 같은 오디오 시계로 계산했습니다.

    1 BGM 예약 재생과 노트 도착 시각을 같은 오디오 시계로

    문제
    리듬 게임은 곡의 n초에 노트가 판정선에 닿아야 합니다. 초기 노트는 고정 스텝 MoveTowards로 움직여, 생성이 늦어진 만큼 도착 시각도 밀리는 구조였습니다.
    판단
    시작 시각 하나를 오디오 엔진 시계(AudioSettings.dspTime)로 정해 BGM 예약과 모든 노트 계산의 기준으로 삼았습니다.
    결과
    생성이 몇 프레임 늦어도 목표 시각은 그대로이고, 노트 위치는 매 프레임 그 목표 시각에서 다시 계산됩니다.

  • DARK SHIELD

    Unity 3D 로그라이트 액션 · 3인 팀 · 2024.11.26~2024.12.12

    분기 포털 스테이지의 생성⁠·⁠정리와 클리어 조건을 만들고, 팀장으로서 세 사람이 만든 매니저를 한 초기화 순서로 묶었습니다.

    1 분기 포털을 만들 때 다음 방만 생성하고, 이동 뒤 지나온 방 정리

    문제
    첫 구조는 분기 없이 선형 방 10개를 시작할 때 모두 만들었습니다. 포털마다 다음 방이 갈라지면 미리 만들 방이 깊이에 따라 곱으로 늘 것으로 봤습니다.
    판단
    포털 색으로 다음 방을 미리 보여 주려면 후보 방은 있어야 했습니다. 그래서 후보 방만 만들고 이동 뒤 필요 없는 방을 지우는 쪽으로 두 번에 걸쳐 바꿨습니다.
    결과
    일반 방으로 이동할 때마다 다음 후보를 만들고, 고르지 않은 방과 지나온 방의 GameObject를 지웁니다.

    장착하면 화면⁠·⁠스탯⁠·⁠DB 값이 같은 이벤트로 갱신되고, 재접속 때 저장값으로 장착 상태를 되살립니다(ea471ce).

    IAmSurvivor

    문제
    업적 조건은 처치 수, 무피격 승리, 체력 비율 승리, 누적 승리처럼 성격이 다릅니다. 조건마다 게임 로직에 if문을 넣으면 조건이 늘 때마다 GameManager가 커집니다.

    결과
    이미 달성한 업적의 조건이 다시 구독되던 문제를 고쳐(1f21e14), 달성한 조건은 알림 대상에 다시 붙지 않습니다.
